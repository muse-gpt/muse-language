# 播客与声音叙事

## 受众

播客主持、访谈节目、音频纪录与声音叙事作者。

## 何时使用

- 人声与章节结构是主产品；画面可选。
- 需要音乐床让位于人声、可感知的章节转场。

以镜头叙事为主 → `muse-filmmaker`；纯主题作曲 → `muse-composer`。

## 工作流

1. 整理听众、节目承诺、嘉宾关系与章节顺序；用 [audio-brief.md](references/audio-brief.md)。
2. `timeline` 表示章节；`intent` 表示亲密 / 紧张 / 调查 / 释疑。
3. `music` 定义音乐床与密度；`orchestrate` 规定音乐何时让位于人声。
4. 需要视频版时再加低干扰 `visual`（背景、字幕安全区、节拍微动），不抢人声注意力。
5. `muse check` → `muse preview`：听人声是否被盖、片头是否过长、章节转场是否可感知。
6. 音频交付：`muse render <script.muse> -o out.wav --format wav`（或 `mp3`）；附章节清单。成片视频边界交给 `muse-publish`。

## 硬约束

- 声音优先：清晰人声与自然停顿重于视觉装饰。
- 不要把没有实际视频编码的 PNG/WAV 预览目录宣称为 MP4。
- 命令失败时报告真实原因；不要伪造“已混音完成”。
- 版权素材与嘉宾授权状态写进交付说明，不默认已获授权。
