# 游戏视听工作流

## 受众

游戏音频、过场动画、关卡预告与交互事件作者。

## 何时使用

- 存在可重复进入/退出的玩家状态（探索、警戒、战斗、低血、胜利、失败等）。
- 需要稳定的 `act`、循环边界与状态切换约束，而不是一次性剪辑。

线性电影叙事 → `muse-filmmaker`；纯主题写作 → `muse-composer`。

## 工作流

1. 列出玩家状态与触发条件；用 [state-brief.md](references/state-brief.md) 做切换表。
2. 每个稳定状态对应一个 `act`（`timeline`）；`tempo` 服务紧张度变化。
3. `music`：动机、调性、密度与层次；`visual`：镜头、粒子与低干扰 UI 相关视觉。
4. `intent` 写状态情绪；`orchestrate` 映射能量到配器密度、镜头速度与转场，并写硬约束（循环边界、淡入淡出、禁止突兀跳调等）。
5. `muse check` → `muse preview`：验证从不同状态进入同一段落时，速度/调性/画面不突兀。
6. 为运行时导出可读的 act / tempo / 资源信息；听感可用 `muse render ... --format wav|mp3`，交换可用 `muse export ... --format midi|musicxml`。

## 硬约束

- 不要把一次性剪辑逻辑硬编码成“只能播一次”的音乐结构。
- 同一 `act` 必须可重复进入；无法保证时明确标为线性过场，而不是交互床。
- 输出应是可解释的段落与规则，不是一段不可拆的黑盒音频。
- 不声称 Muse 已内置完整游戏引擎状态机；本 skill 交付的是可复用时间线合同。
