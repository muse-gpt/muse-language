# 游戏视听工作流

先列出玩家状态和触发条件：探索、警戒、战斗、低血量、胜利、失败或回到安全区。把可重复进入和退出的段落设计成稳定的 act，不把一次性剪辑逻辑硬编码进音乐。

用 `music` 定义动机、调性、密度和层次，用 `visual` 定义镜头、粒子和 UI 相关视觉，用 `orchestrate` 映射能量到配器、镜头速度和转场。明确循环边界、淡入淡出和状态切换的硬约束。

验证同一段落从不同状态进入时不会产生突兀的速度、调性或画面跳变。为运行时系统输出可读的 act/tempo/asset 信息，而不是只交付一段不可解释的音频。

需要设计状态切换表时读取 [state-brief.md](references/state-brief.md)。
